# 项目 3 结果：用 Sentinel-2 看水道口羽流

> 完成日期：2026-11-16  
> 结论一句话：**乌龙水道看不到羽流信号；德国水道有弱信号，指向"在 Malakal 高潮前后转外流"，和简报现在用的 0 分钟延迟一致，但精度不够，不能用来校准。简报里的延迟不改。**

## 1. 做了什么

| 步骤 | 内容 | 结果 |
|---|---|---|

## 2. 必须先知道的限制：过境时间把"涨落潮"和"大小潮"绑在一起
卫星每天固定在 10:35 左右过境，所以：

- 涨潮时拍到的几乎都是小潮日；
- 落潮时拍到的几乎都是中潮、大潮日。

在潮差 0.8–1.4 m 的"可比"日子里，无云影像只有约 10 张涨潮、约 50 张落潮。模型里加了潮差项来处理这个问题，但涨潮一侧的样本始终偏少，这是误差范围宽的主要原因。

## 4. 结论和对简报的影响
1. **`sites.json` 里两个水道的转流延迟保持 0 分钟，不改。**
2. 德国水道的卫星估计为"高潮后 0 到 +40 分钟开始外流"。羽流要过一段时间才会被看到，卫星估计本来就会偏晚，所以实际转流应在 Malakal 高潮前后或更早一点。这和项目 1（水位差在高潮前 35–40 分钟反转）互相支持，**算是现有设定的一个独立旁证**，但不够精确，不能用来校准。
3. 乌龙：这个方法测不出来。原因很可能是出水口外是陡峭礁墙直下深海，泻湖水出来马上被稀释、被沿岸流带走，加上泻湖本身的水就很清。
4. 顺带修正了 `sites.json` 里两个水道的坐标。只影响显示，不参与计算：
   - 乌龙：7.299 / 134.243 → **7.2833 / 134.2456**（出水口）
   - 德国：7.163 / 134.265 → **7.1210 / 134.2720**（出水口）

## 5. 还可以做的（都不急）
- **潜水记录**仍然是校准延迟最直接的办法：每次在乌龙、德国记下"什么时候转流"，攒到 10–15 条就能把误差压到 ±20 分钟左右。
- **Sentinel-1 雷达**（06:20 / 18:20 过境）能拍到其他潮汐阶段，但雷达看到的是海面粗糙度和流隔线，不是浑浊度。成功率不确定，投入大约 1–2 天。建议有了潜水记录再决定。
- **取样框**目前是草稿，Lowis 可以在 QGIS 里修改：
  - 德国 OUT1 所在的湾顶可能偏浅、看得到海底，影响颜色；
  - 乌龙 IN 框放在了水道北侧的深坑，不在水道正中。
  改完我可以再跑一次，约 15 分钟，但预计结论不会变。
